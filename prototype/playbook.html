Playbook

How to pass the bug-fixing round

This page is built from real reports by people who took the Amazon test. Sources are at the bottom. Read it once (about 8 minutes), then practise on the levels.

1 · What it is 2 · 60-minute plan 3 · Fixing one bug 4 · Reading new code fast 5 · Common bugs 6 · Hidden tests 7 · Using the AI 8 · Spring Boot Sources

01What the round is

  • The Amazon online test has a coding part with two questions: a normal coding puzzle, and a bug-fixing task in an app someone else wrote.
  • You pick the language. People report Node (MERN), Spring Boot and Django.
  • The time varies. A common report: 40 minutes for the puzzle and 60 for the bug task. Your invite email has the real numbers.
  • The number of bugs varies, from 3 bugs to about 6 failing tests. Apps people got: car rental, support tickets, movie search, password reset.
  • There's an AI helper built in. The test is watched (camera on), and you're responsible for every line you submit.
  • There are hidden tests you can't see. They check things like empty input, limits, saving, permissions and repeated actions.
What they really want to see: you can open code you've never seen, find what's wrong, prove it, and make a small, safe fix without breaking anything else.

02The 60-minute plan

0–8Look around
8–48Fix bugs, about 10 min each, easiest first
48–55Hidden-test check
55–60Review changes
  • Run the tests before you read any code. The names of the failing tests are your to-do list.
  • Fix the easiest one first. An early win calms you down, and one fix (like the error handler) often fixes several tests.
  • Give each bug about 10 minutes. If you're stuck, write down your guess and move on. The bugs are usually separate.
  • Change one thing, then run ALL the tests. Never stack three guesses on top of each other.
  • Save the last 10 minutes for the hidden-test list below and a final look at your changes.

03How to fix one bug

1Read the failure"Expected X, got Y" is your clue. 500 = something crashed. Empty = something wasn't awaited. Wrong data = wrong logic.
2Follow the requestRoute → controller → service → database. Write down the path.
3GuessSay it in one sentence: "The id is undefined because the route calls it ticketId."
4Prove itAdd one console.log where you think it breaks. Run again. Don't fix what you haven't proved.
5Small fixChange as little as possible. Run all the tests. Remove the log.
What the failure tells you:
{} or [{},{}] → a missing await or Promise.all
500 → something crashed, or the error handler reads the wrong field
ERR_HTTP_HEADERS_SENT → a missing return after sending a reply
too much data → a filter is undefined, or there's no owner check
right reply, but wrong when you load it again → it wasn't saved, or an old cached copy was served
works alone, fails when two requests run at once → two requests clashing

04Reading new code in 5 minutes

  1. README and package.json: how to run the tests, and which libraries are used.
  2. app.js: the order of middleware, where routes are attached, and whether there's an error handler.
  3. Routes file: the list of endpoints. Note every :name in the paths.
  4. The test file: how tests log in (headers? tokens?) and what they expect back.
  5. Models, errors, constants: field names, status names, error codes.

Skip any file that no failing test touches. Your job is fixing bugs, not tidying code.

05Common bugs (Node / Express / Mongo)

Almost every planted bug is one of these. Learn to spot them on sight. Red is the bug, green is the fix.

Missing await

The reply is {}, or the data shows up "later".

const todo = repo.create(data);
res.json(todo); // {}
const todo = await repo.create(data);

Missing return after a reply

The function keeps running after sending a reply.

if (!title) res.status(400).json(err);
await repo.create(...)
if (!title) return res.status(400).json(err);

async map without Promise.all

You get a list of {}.

return list.map(async t => ({...t, n: await count(t)}));
return Promise.all(list.map(async t => ...));

URL values are text

They don't match true/false or numbers, and + glues them together.

filter.done = req.query.done;     // 'true'
skip + req.query.limit            // '22'
filter.done = req.query.done === 'true';
const limit = Number(req.query.limit) || 10;

Wrong route name

The value is undefined, so you get "not found".

router.post('/:ticketId/replies', ...)
req.params.id
req.params.ticketId

undefined in a filter → returns everything

{owner: undefined} becomes {}, so everyone's data leaks.

find({ owner: req.user.userId }) // field doesn't exist
find({ owner: req.user.id })

No owner check

The list is filtered, but /:id routes aren't.

const car = await Car.findById(id);
const car = await Car.findOne({ _id: id, owner: user.id });
if (!car) return 404;

Changed but not saved

The reply looks right. Loading it again shows the old value.

Object.assign(doc, changes); return doc;
await doc.save();   // or updateOne / findByIdAndUpdate

Old cached data

Saving doesn't clear the saved copy.

addCar(): save only
addCar(): save, then cache.del(key(owner))

Error handler reads the wrong field

Every 404/403/409 becomes a 500.

res.status(err.statusCode || 500) // error uses .status
res.status(err.status || 500)

|| vs &&

Write the rule in plain words, then check the operator.

if (!isAuthor || !isAgent) forbid();
if (!isAuthor && !isAgent) forbid();

Capitals don't match

The check never fires.

status === 'CLOSED'   // saved as 'closed'
status === STATUS.CLOSED

Sort returns true/false

Sorting quietly does nothing.

arr.sort((a, b) => a.price > b.price)
arr.sort((a, b) => a.price - b.price)

Missing brackets with ? :

a || b ? x : y runs as (a || b) ? x : y.

b.r - a.r || a.t > b.t ? 1 : -1
b.r - a.r || a.t.localeCompare(b.t)

indexOf used as true/false

0 counts as false, and -1 counts as true.

if (ALLOWED.indexOf(field)) reject();
if (!ALLOWED.includes(field)) reject();

Off by one

Test page 1, the last page, and the exact limit.

skip = page * limit;   rating: {$gt: min}
skip = (page - 1) * limit;   rating: {$gte: min}

Unsafe search pattern

"nolan" doesn't match "Nolan", and "(500" crashes.

{ title: { $regex: q } }
{ title: { $regex: escape(q), $options: 'i' } }

Two requests clash

Both see "1 left" and both buy it.

if (p.stock >= qty) await setStock(p.stock - qty);
findOneAndUpdate({_id, stock: {$gte: qty}},
                 {$inc: {stock: -qty}})

Half-finished save

Item 1 is saved, item 2 fails, and nothing undoes item 1.

for (i of items) { check(i); save(i); }
check all → save all → undo if anything fails

Comparing objects instead of ids

Two objects are never equal, even with the same values.

list.includes({ movieId })
a._id === b._id     // Mongo ObjectIds
list.some(i => i.movieId === movieId)
String(a._id) === String(b._id)

Changing a shared list

.sort(), .reverse() and .splice() change the original list, which every request shares.

return products.sort(cmp);
return [...products].sort(cmp);

Money rounding

Round once, at the end. Watch the brackets.

Math.round(total * 100 / 100)
Math.round(total * 100) / 100   // or store paise

= inside a condition

It sets the value instead of comparing. It's always true and changes data.

items.find(i => i.sku = sku)
items.find(i => i.sku === sku)

reduce with no start value

The first item becomes the total, and an empty list crashes.

items.reduce((s, i) => s + i.price)
items.reduce((s, i) => s + i.price, 0)

Missing break in a switch

A case without break runs the next case too.

case 'local': fee = 40;
case 'regional': fee = 60; break;
case 'local': return 40;
case 'regional': return 60;

^ is not "power of"

In JavaScript, power is **.

BASE * 2 ^ n
BASE * 2 ** n

async inside forEach

forEach doesn't wait, so the reply goes out first.

list.forEach(async x => await save(x));
res.json(...)
await Promise.all(list.map(save));

|| 'text' is always true

Any non-empty text counts as true.

if (role === 'admin' || 'owner')
if (role === 'admin' || id === p.ownerId)

|| turns 0 into the default

0, '' and false all count as "missing".

const t = Number(q.threshold) || 5;
const t = q.threshold === undefined ? 5 : Number(q.threshold);

Numbers and true/false saved as text

As text, '9' comes after '10', and 'false' counts as true.

if (item.stock <= '10')   if (!flag.enabled)
Number(item.stock) <= 10   flag.enabled === true || flag.enabled === 'true'

Seconds vs milliseconds

Date.now() is in milliseconds. Token exp and Retry-After are in seconds.

now + 15 * 60     diff / 86400
now + 15 * 60 * 1000     diff / 86_400_000

splice(indexOf(x), 1)

If x isn't there, indexOf is -1, which removes the LAST item.

arr.splice(arr.indexOf(id), 1)
const i = arr.indexOf(id); if (i === -1) return 404;

Middleware order

Express runs things top to bottom. A route above use(auth) skips the login check.

app.get('/admin', h); app.use(auth);
app.use(auth); app.get('/admin', h);

Filter overwritten

Setting the same field twice keeps only the second.

f.price = {$gte: min}; f.price = {$lte: max};
f.price = { $gte: min, $lte: max };

Memory wiped on every call

Anything created inside a function starts fresh each time.

function topUp() { const seen = new Map(); ... }
save the key in the database

Time slots overlapping

10:00–10:30 and 10:30–11:00 do NOT overlap.

a.start <= b.end && b.start <= a.end
a.start < b.end && b.start < a.end

Average of averages

A day with 1 sample shouldn't count as much as a day with 100.

mean(days.map(d => d.avg))
totalSum / totalCount

Cache mistakes

The key must include the page/query. Never change the cached object.

key = req.path;  data.items.forEach(i => i.price *= 1.18)
key = req.url;   items.map(i => ({ ...i, gst: ... }))

06Hidden-test checklist (use it in the last 10 minutes)

  • Missing, empty, or spaces-only input → 400
  • 0, negative numbers, text instead of a number
  • Exact limits: equal to the limit, the last page, past the end
  • Another user's item on every /:id route → 404 or 403
  • No login header → 401
  • After every save: load it again and check it stuck
  • A failed save leaves nothing half-changed
  • Doing the same thing twice: close twice, delete a missing item, add a duplicate
  • Retries with the same key, and requests with no key
  • Two requests at once on anything with a count (stock, seats, money)
  • Status codes: 201 for create, and 404 vs 400 vs 409
  • Reply shape unchanged: same fields, same types

07Using the AI helper safely

  • Find the failure first, then ask the AI. "Fix this bug" gets you a confident rewrite of the wrong file.
  • Give it one small job: "explain this function", "where is req.user used?", "why could this return {}?"
  • Read every line it changes. Watch for edited tests, renamed routes, or changed reply shapes.
  • Never edit the tests to make them pass, unless the task says a test is wrong.
  • Don't paste the test's code into outside tools.

A prompt that works

The app: Express + Mongoose. The request goes POST /tickets/:ticketId/replies → ticketController.addReply → ticketService.addReply.
Expected: 201 with the reply (test "customer can reply to a ticket").
What happens: 404 "Ticket not found". console.log(ticketId) in the service prints undefined.
Only look at: ticketController.js and ticketService.js. Don't touch tests or routes.
Please: explain the most likely cause in 2 sentences, then suggest the smallest change.
